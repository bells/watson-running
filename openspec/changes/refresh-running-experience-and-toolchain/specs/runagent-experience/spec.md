## Purpose

使 RunAgent 对话体验与跑步记录站点一致，同时明确新后端能力进入前端前必须满足的契约、隐私、可靠性和部署条件。

## ADDED Requirements

### Requirement: 现有开发聊天保持可靠

Classic 的开发环境聊天 SHALL 延续现有单轮 `/api/chat` 契约，只发送当前问题，保留超时、取消、手动重试和安全渲染行为，并采用站点共享视觉与可访问交互。生产静态站点 SHALL 不显示尚未部署的聊天入口。

#### Scenario: 提问与取消
- **WHEN** 用户在开发环境发送合法问题、取消等待或关闭聊天
- **THEN** 界面以一致的状态反馈显示等待、回答或取消，迟到响应不得覆盖当前会话

#### Scenario: 静态生产构建
- **WHEN** 站点以当前静态生产方式构建
- **THEN** 不显示聊天入口，不向本地开发代理或未部署的 RunAgent 发送请求

### Requirement: 已实现后端能力的契约就绪门槛

在前端启用 Streaming Chat 或 Agent 交互前，两个仓库 SHALL 有对应的版本化、显式类型契约和共享测试样例，覆盖请求与响应字段、SSE 事件、终态、错误码、超时、取消及重试边界。未版本化的 `/api/chat/stream` 与 `/api/agent` SHALL 作为后端现状记录，不被当作正式前端生产契约。

#### Scenario: 契约未就绪
- **WHEN** 后端只有未版本化接口，或尚无双仓库一致的契约样例
- **THEN** 前端不启用面向公众的 Streaming Chat 或 Agent 入口，文档明确现有接口与待发布契约的差异

#### Scenario: 契约就绪
- **WHEN** 双仓库确认版本化请求、响应、错误和流事件样例
- **THEN** 前端可在后续里程碑以类型检查和契约测试验证客户端实现，不依赖异常消息或未声明字段猜测状态

### Requirement: 数据感知回答有明确边界

任何计划中的数据感知问答 SHALL 只依赖经过审查的只读、最小化活动数据，并向用户明确区分有数据支持的结果与一般建议。原始轨迹、精确起终点、平台凭据和私有备注 SHALL 不自动进入浏览器请求或模型上下文。Agent 会话标识 SHALL 不被视为身份认证或授权。

#### Scenario: 询问个人跑量
- **WHEN** 用户询问个人距离、配速、PB 或近期活动且经审查的数据源不可用
- **THEN** 未来的数据感知界面明确说明无法核实个人数据，不把推测当作真实纪录

#### Scenario: 会话与隐私
- **WHEN** 未来 Agent 客户端使用 `conversationId` 或附带活动上下文
- **THEN** 前端只按已确认契约传递非敏感最小字段，不以会话 ID 代替服务端身份校验
